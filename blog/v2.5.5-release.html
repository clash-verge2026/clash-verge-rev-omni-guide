Clash Verge Rev v2.5.5 发布：服务模式与 DNS 覆写深度修复

👤 Clash Verge Rev 核心团队 📅 2026-09-24 ⏱️ 阅读时间约 9 分钟
v2.5.5 是一个以“服务层稳定性”为核心主题的版本。在过去几周中，我们集中处理了服务模式拉起、DNS 覆写异常、扩展覆写优先级冲突以及 Windows/Linux 服务安装与回退等一系列问题。这些问题的共同特点是：它们不影响所有用户，但一旦触发就会导致内核无法启动、配置错误覆盖或服务状态错乱——恰恰是最难排查的类型。本版本通过系统性的修复与优化，让服务模式与配置覆写这两个高级功能变得更加可靠。

🛠️ 服务模式与缓存：解决内核无法启动的顽疾

服务模式是 Clash Verge Rev 在 Windows 和 Linux 上实现特权操作（如 TUN 设备创建）的关键机制。v2.5.5 修复了其中几个长期存在但难以复现的问题：

多来源缓存冲突导致内核启动失败

当你从多个订阅或规则集引用同一个缓存目录时，服务模式下的内核可能因为缓存文件竞争而无法正常启动。这是一个典型的并发问题——两个来源同时尝试写入或读取同一缓存文件，导致状态不一致。v2.5.5 通过引入缓存路径的独立命名空间解决了这个问题。

文件类错误日志缺乏可操作性

过去，当服务模式因文件问题启动失败时，日志往往只显示一个泛泛的错误信息，用户无法得知具体是哪个文件、什么原因。现在，错误日志会明确显示具体路径和失败原因，例如“无法写入 /path/to/cache/config.yaml：权限不足”。这看似是一个小改动，却能显著缩短排查时间。

🌐 DNS 覆写：从“误覆盖”到“精确控制”

DNS 覆写是 Clash Verge Rev 中一个强大但容易出错的机制。它允许用户通过 Merge 或 Script 覆盖订阅中的 DNS 配置。v2.5.5 修复了一系列与覆写行为相关的边界问题：

问题修复后的行为
空内容提交报错空提交现在被正确识别为“无操作”，不再抛出错误
初始值覆盖已有配置初始值仅在字段为空时填充，不再覆盖用户已填内容
已填字段仍残留原配置覆写后旧条目被正确清理，不再残留
空字段在高级编辑器中缺失空字段现在也会显示，便于用户明确知道哪些字段可填
Merge/Script 误覆盖已填字段已填字段受到保护，未填字段继续采用扩展配置
覆盖 DNS 策略/hosts 时旧条目未清理覆写时正确清理旧条目，避免配置叠加
💡 设计原则：本次修复确立了一个明确的优先级规则——用户显式填写的字段 > 扩展配置 > 订阅默认值。这意味着你在 UI 中手动填写的 DNS 设置，不会再被 Merge 或 Script 意外覆盖。

🔐 服务、权限与 Sidecar：修复状态错乱

Sidecar 模式是 Clash Verge Rev 在不具备服务权限时的降级方案。v2.5.5 修复了服务与 Sidecar 之间的状态同步问题：

  • 数据目录所有权不匹配：首次以管理员身份启动后，数据目录可能归属于管理员账户，导致系统服务（以 SYSTEM 或 root 运行）拒绝启动内核。现在内核会检测所有权并在必要时提示修复。
  • 服务重装后内核缺失：重新安装服务后，内核二进制文件可能未被正确复制，导致 Sidecar 无法继续使用。此问题已修复。
  • 首页误显示服务模式：当内核未运行时，首页不再错误地显示“服务模式”状态，避免误导用户。
  • 重复请求管理员授权：服务重装过程不再重复弹出 UAC 或 sudo 授权请求。
  • 卸载后误报失败：服务卸载后不再错误地报告“卸载失败”。

这些修复共同解决了“服务状态混乱”这一用户体验痛点——过去用户常常不确定自己当前运行在内核模式还是服务模式，现在状态显示更加准确可信。

🪟🐧 平台专项：Windows 与 Linux 的服务安装与回退

Windows

  • 当服务因路径或目录权限无法启动时，界面现在会增加重新安装服务的提示，而不是让用户对着错误信息发呆。
  • 修复了服务回退检查失败后状态未更新的问题——现在可以正常重新尝试 Sidecar 模式。

Linux

  • 修复了安装或修复服务后，内核仍无法启动、TUN 模式无法开启的问题。这主要影响使用 systemd 服务的 Debian/Ubuntu 和 Fedora/RHEL 用户。
⚠️ Linux 用户注意：如果你之前遇到过“服务安装成功但 TUN 模式仍然无法开启”的情况，v2.5.5 应该能解决。如果问题依旧，请检查 /dev/net/tun 的权限设置。

⚡ 优化改进：让高级功能更易用

扩展覆写编辑窗口的透明化

扩展覆写（Merge 和 Script）是 Clash Verge Rev 的高级功能，但很多用户不清楚其执行顺序和优先级。v2.5.5 对编辑窗口进行了大幅改进：

  • 标明作用范围：每个编辑窗口现在清楚显示它会影响哪些配置段。
  • 标注执行顺序：Merge 和 Script 的执行顺序现在可视化展示，避免混淆。
  • 突出当前步骤：编辑时当前正在配置的步骤会高亮显示。
  • 应用设置优先级提示：当扩展配置尝试写入由应用设置托管的字段时，界面会提示“该值未生效”，并在扩展日志中标注。

DNS 覆写开关的按订阅记忆

DNS 覆写开关现在会按订阅分别记忆。自动关闭只影响当前订阅，并会提示影响范围。这意味着你可以为不同的订阅设置不同的 DNS 覆写策略，而不必担心切换订阅时设置被重置。

系统服务兼容性检查

升级后，如果服务版本或协议不兼容，客户端会提示重新安装服务。这避免了因服务与新客户端版本不匹配而导致的隐蔽故障。

预构建资源补充

本版本补充了 ASN 数据库文件到预构建资源中。这意味着使用 ASN 规则的配置在首次运行时无需额外下载，启动更快、更可靠。

❓ 常见问题

Q：升级后提示“服务版本不兼容”怎么办？
A：这是新版加入的兼容性检查。请在“设置 → 服务”中点击“重新安装服务”，客户端会自动部署匹配当前版本的服务组件。
Q：Linux 下 TUN 模式仍然无法开启？
A：请确认：1）服务已正确安装（systemctl status clash-verge-service）；2）/dev/net/tun 存在且当前用户有读写权限；3）内核模块已加载（lsmod | grep tun）。如果问题依旧，欢迎提交 Issue 并附上服务日志。
Q：DNS 覆写开关现在按订阅记忆，会不会导致混乱？
A：不会。每个订阅的开关状态独立保存，切换订阅时会自动恢复对应的状态。界面会提示当前订阅的覆写状态及影响范围。
Q：第三方服务“狗狗加速”与本仓库的关系？
A：该服务非本仓库运营，仅为社区用户分享的资源。请自行判断其可靠性与安全性，本仓库不承担相关责任。

🏁 结语

v2.5.5 是一次“向内看”的版本——它没有引入耀眼的新功能，而是把精力放在了服务层、覆写逻辑和跨平台安装体验的打磨上。这些改进不显山露水，却能显著减少那些“莫名其妙无法启动”的困扰。正如我们在 v2.5.2 中强调的：稳定性是体验的基石。感谢每一位在 Issues 中提供详细日志和复现步骤的用户——正是你们的反馈，让这些问题被及时发现并修复。
