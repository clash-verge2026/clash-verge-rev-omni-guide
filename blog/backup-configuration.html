配置备份与恢复全攻略：让你的代理环境永不丢失

👤 Clash Verge Rev 核心团队 📅 2026-07-14 ⏱️ 阅读时间约 12 分钟
你花了数小时精心调校的代理规则、反复测试的 DNS 配置、精挑细选的节点列表——如果因为一次系统重装、硬盘故障或误操作而全部丢失，那将是巨大的时间和精力损失。Clash Verge Rev 的配置看似只是一个 YAML 文件，但围绕它构建一套完善的备份、版本管理与灾难恢复体系，能让你在任何意外面前从容应对。本文将从最基础的手动备份开始，逐步深入到自动化脚本、Git 版本控制、云同步乃至完整的灾备演练方案。

🗂️ 配置到底存在哪里？认识你的“数据资产”

在开始备份之前，首先要搞清楚 Clash Verge Rev 的配置数据散落在哪些位置。很多人以为只有一个 config.yaml，实际上完整的用户数据包含以下部分：

位置内容重要性备份建议
~/.config/clash-verge-rev/应用主数据目录（Linux）极高整体备份
%APPDATA%/io.github.clash-verge-rev/应用主数据目录（Windows）极高整体备份
~/Library/Application Support/io.github.clash-verge-rev/应用主数据目录（macOS）极高整体备份
config.yaml主配置文件极高必须备份
profiles/多配置切换的额外配置文件高按需备份
ruleset/RULE-SET 缓存文件中可不备份（可重新下载）
logs/运行日志低不需要备份
cache/内核缓存与 GeoIP 数据库低不需要备份
💡 核心原则：最需要保护的是 config.yaml 主配置文件，以及你可能手动修改过的任何 .yaml 文件。RULE-SET 缓存、日志和 GeoIP 数据库都可以在需要时重新下载，无需占用备份空间。

📋 方案一：手动备份——最简单也最可控

手动备份适合不频繁修改配置的用户，或者作为自动化方案的补充。Clash Verge Rev 的“配置”面板中提供了一键导出功能，可以将当前生效的完整配置（合并了订阅和本地修改后的最终结果）导出为一个 YAML 文件。

1 从 UI 导出配置

打开 Clash Verge Rev → 设置 → 配置 → 点击“导出配置”。选择一个安全的目录（如 Documents/backups/clash/）保存，建议文件名包含日期，如 config-2026-07-15.yaml。

2 手动复制数据目录

如果你想备份包括订阅缓存、规则集在内的完整环境，可以直接将整个数据目录打包。在终端中执行：
Linux/macOS：tar -czf clash-backup-$(date +%Y%m%d).tar.gz ~/.config/clash-verge-rev/
Windows (PowerShell)：Compress-Archive -Path "$env:APPDATA\io.github.clash-verge-rev" -DestinationPath "clash-backup-$(Get-Date -Format 'yyyyMMdd').zip"

3 存储到安全位置

将导出的文件复制到至少两个不同的物理位置——例如本地硬盘一份、U 盘或移动硬盘一份。如果你有 NAS，也可以通过网络共享自动同步。

⚠️ 安全提醒：配置文件中包含你的代理节点信息和订阅地址。备份文件应妥善保管，不要上传到公开的网盘或代码仓库中。如果必须使用云存储，建议先对文件进行加密（见后文）。

🤖 方案二：自动化脚本——设置一次，永久运行

如果你经常修改配置，手动备份很容易忘记。编写一个简单的自动化脚本，配合操作系统的定时任务，可以做到“无感备份”。

跨平台 Bash 脚本示例

#!/bin/bash # clash-backup.sh — 自动备份 Clash Verge Rev 配置 BACKUP_DIR="$HOME/Documents/clash-backups" CONFIG_DIR="$HOME/.config/clash-verge-rev" RETENTION_DAYS=30 # 保留最近 30 天的备份 mkdir -p "$BACKUP_DIR" TIMESTAMP=$(date +%Y%m%d-%H%M%S) tar -czf "$BACKUP_DIR/clash-config-$TIMESTAMP.tar.gz" \ "$CONFIG_DIR/config.yaml" \ "$CONFIG_DIR/profiles/" 2>/dev/null # 清理过期备份 find "$BACKUP_DIR" -name "*.tar.gz" -mtime +$RETENTION_DAYS -delete echo "✅ 备份完成：clash-config-$TIMESTAMP.tar.gz"

设置定时任务

Linux/macOS (crontab)：执行 crontab -e，添加一行 0 3 * * * /home/yourname/clash-backup.sh，表示每天凌晨 3 点自动备份。
Windows (任务计划程序)：打开“任务计划程序” → 创建基本任务 → 触发器设为“每天” → 操作设为“启动程序”，程序填 powershell.exe，参数填你的备份脚本路径。

💡 进阶玩法：在脚本末尾添加一行 git -C "$BACKUP_DIR" add -A && git -C "$BACKUP_DIR" commit -m "auto backup $TIMESTAMP"，将备份目录本身也纳入 Git 管理，实现备份的版本追踪。

📜 方案三：Git 版本控制——每一次修改都有据可查

配置文件本质上就是文本文件，天然适合用 Git 管理。每次修改后提交一次，你就拥有了完整的变更历史，可以随时回退到任意历史版本。

1 初始化 Git 仓库

在配置目录下初始化一个私有的 Git 仓库：cd ~/.config/clash-verge-rev && git init。注意：这个仓库只应该存在于你的本地机器上，绝对不要推送到公共 GitHub。

2 编写 .gitignore

排除不需要版本控制的文件，创建 .gitignore：

# Clash Verge Rev .gitignore logs/ cache/ ruleset/ # 可重新下载，无需追踪 *.db # 数据库文件

3 建立提交习惯

每次修改配置后执行：git add config.yaml && git commit -m "优化 ChatGPT 路由规则"。清晰的 commit message 能让你在数月后依然明白当时为什么这样改。

4 （可选）推送到私有远程仓库

如果你需要在多台设备间同步配置，可以创建一个私有 GitHub 仓库，或使用自建的 Gitea/GitLab 实例。在推送前请务必确认 .gitignore 已排除了敏感信息，或使用 git-crypt 对敏感文件加密。

🚨 严重警告：永远不要将包含真实节点信息和订阅地址的配置文件推送到公共仓库。即使用私有仓库，也建议对订阅地址和密码字段进行脱敏处理，或使用 Git 的 smudge/clean 过滤器自动替换敏感值。

☁️ 方案四：云端同步——多设备无缝切换

对于在台式机、笔记本和 VPS 上同时使用 Clash Verge Rev 的用户，云同步方案可以让配置在设备间保持一致。

同步方案优点缺点推荐场景
Syncthing点对点加密、无中心服务器、实时同步需要设备同时在线多设备局域网同步
私有 Git 仓库版本历史、冲突解决、跨互联网需手动 pull/push开发者、有 Git 使用习惯
加密云盘（如 Cryptomator + Dropbox）端到端加密、大容量、多平台依赖第三方服务注重隐私的普通用户
iCloud Drive / OneDrive系统内置、零配置明文存储、隐私风险对隐私要求不高的用户

我个人推荐 Syncthing + 私有 Git 仓库 的组合：Syncthing 负责实时同步配置文件到所有设备，Git 仓库负责保留历史版本和变更记录。两者互补，兼顾便捷性和可追溯性。

🔐 安全加密：保护你的节点信息

无论使用哪种备份方案，只要备份文件离开你的本地设备（上传到云端、复制到 U 盘），都应该进行加密。以下是两种实用的加密方法：

方法一：GPG 对称加密

# 加密（输入密码） gpg --symmetric --cipher-algo AES256 clash-config.tar.gz # 解密 gpg --decrypt clash-config.tar.gz.gpg > clash-config.tar.gz

方法二：age 现代加密工具

age 是一个更简洁的现代加密工具，使用密码短语即可加密文件：

# 加密 age -p -o clash-config.tar.gz.age clash-config.tar.gz # 解密 age -d -o clash-config.tar.gz clash-config.tar.gz.age
💡 最佳实践：将加密后的备份文件存储到云端（如 Google Drive、Dropbox），即使云服务商的数据泄露，攻击者也无法在没有密码的情况下解密你的配置。

🆘 灾难恢复：从零开始重建

备份的真正价值在恢复时才能体现。下面是完整的恢复流程，建议在安全的环境中实际演练一次，确保在真正需要时不会手忙脚乱。

1 安装 Clash Verge Rev

从下载页面获取最新版本并完成安装。首次启动后，客户端会生成一个默认的空白配置文件。

2 解密备份文件（如果加密了）

使用 gpg --decrypt 或 age -d 解密备份文件。如果是 Git 仓库，直接 git clone 到配置目录即可。

3 还原配置文件

关闭 Clash Verge Rev，将备份的 config.yaml 和 profiles/ 目录复制到对应的数据目录中。重新启动客户端，配置即生效。

4 验证与修复

启动后，检查“日志”面板是否有错误信息。由于 RULE-SET 缓存可能已过期，建议在设置中点击“刷新规则集”，让内核重新下载最新的规则文件。确认代理功能正常后，恢复完成。

⚠️ 演练建议：至少每季度进行一次“灾备演练”——在虚拟机或备用电脑上尝试从备份完全恢复配置。这不仅验证了备份文件的完整性，也让你熟悉恢复流程，避免真实灾难时的手足无措。

🏆 最佳实践总结

将以上方案组合起来，就形成了一套完整的配置灾备体系：

  • 每日：自动化脚本定时打包配置文件，保留最近 30 天的历史备份。
  • 每次修改后：使用 Git 提交变更，附带清晰的 commit message。
  • 每周：将加密后的备份文件同步到云端或 NAS。
  • 每月：检查备份文件的完整性，清理过期备份。
  • 每季度：执行一次完整的灾难恢复演练。

这套体系投入的时间成本极低——初次设置大约需要 30 分钟，之后几乎全自动运行。但它在关键时刻能为你节省数小时甚至数天的重新配置时间，更重要的是，它保护了你精心积累的配置经验和调优成果。

🏁 结语

配置备份不是一个“可选”的操作，而是每一位重度用户都应该纳入日常习惯的基础实践。Clash Verge Rev 本身提供了便捷的导出功能，配合 Git 版本控制、自动化脚本和加密云同步，你可以轻松构建一套可靠的配置灾备体系。希望这篇文章能帮助你建立起对配置管理的系统性认知，让你的代理环境真正实现“永不丢失”。
