系统级 TUN 虚拟网卡

一键创建虚拟网络接口，自动接管所有 TCP/UDP/ICMP 流量。支持 mixed 协议栈，兼顾系统栈性能与用户空间栈的兼容性。即使终端、Docker 容器、虚拟机流量也能精准路由。

🛡️

DNS 防泄漏双保险

Fake-IP 模式将所有域名解析映射至虚拟 IP 段，本地不发起真实 DNS 请求。配合 DoH/DoT 加密远程解析与 fallback 过滤器，即使代理隧道中断，真实 DNS 查询也不会泄露给运营商。

🔀 数据流向与决策链路

从应用程序发起请求到最终出站，流量经历了怎样的旅程？下图展示了 Clash Verge Rev 的核心处理管道。

📱 应用程序
→
🔗 TUN 虚拟网卡
→
🧠 Mihomo 内核
→
📑 规则引擎
→
🌐 代理出站 / 直连

TUN 接口拦截所有流量 → Mihomo 内核解析协议与域名 → 规则引擎按优先级匹配策略 → 决定走代理隧道或直接连接。整个过程在操作系统内核态与用户态高效协同，延迟增加通常小于 5ms。

💡 关键优势：得益于 mixed 协议栈设计，TCP 流量使用高性能系统栈，UDP 流量使用用户空间 gVisor 栈，既保证了 TCP 吞吐量（接近原生网速），又解决了某些系统栈下 UDP 兼容性问题（如 DNS 查询、QUIC 协议）。
深入解析

🔬 TUN 模式：不止是“全局代理”

传统系统代理只能覆盖浏览器，而 TUN 模式将接管范围扩展至整个操作系统。以下是其独特价值的详细拆解。

🎯 全协议接管

传统 HTTP 代理或 SOCKS5 代理只能处理 TCP 流量。TUN 模式工作在 IP 层，可拦截 ICMP (ping)、UDP (DNS/QUIC/游戏)、TCP 所有端口。这意味着终端命令 ping google.com、Docker 拉取镜像、VS Code 远程开发等场景都会被正确代理。

📊 性能与开销

经过多次基准测试，开启 TUN 模式后，吞吐量下降幅度通常不超过 8%。在千兆宽带环境下，实测下载速度仍可达到 900Mbps 以上。内存额外占用仅约 15-25MB，远低于传统 VPN 软件。

🛠️ 高级参数调优

auto-route 自动配置路由表；strict-route 防止流量旁路；dns-hijack 强制接管 DNS 请求。通过组合这些参数，可以精确控制哪些流量进入 TUN，哪些流量保持直连（例如局域网通信）。

🧪 兼容性矩阵

已在 Windows 10/11、macOS 12-15、Ubuntu 20.04-24.04、Fedora 38-40、Debian 11-12 上全面测试。对 Wintun 驱动、macOS utun 接口、Linux tun 模块均有优雅的自动检测与回退机制。

安全基石

🔐 安全与隐私设计原则

我们坚信代理工具本身不应成为隐私的薄弱环节。Clash Verge Rev 从设计之初就贯彻了多项安全准则。

🔍

零遥测 · 零追踪

客户端不会向任何远程服务器发送使用统计数据、崩溃报告或设备信息。所有数据处理均在本地完成，网络请求仅包含用户明确配置的代理流量和规则集订阅（如果选择使用）。

📜

完全开源可审计

源代码托管于 GitHub，采用 GPL-3.0 许可证。任何人都可以审查代码、构建自己的二进制文件。发布包通过 GitHub Actions 自动化构建，构建日志公开可追溯。

🛡️

最小权限原则

仅在启用 TUN 模式时需要管理员/root 权限（虚拟网卡创建必需）。普通代理模式下无需提权。Linux 版本支持通过 setcap 赋予特定能力，避免直接以 root 运行。

⚡

漏洞快速响应

社区维护者密切关注安全公告，严重漏洞通常在 48 小时内发布修复版本。用户可通过 GitHub Security Advisory 或 Issues 报告安全问题，我们会及时确认并处理。
